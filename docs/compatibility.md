# Compatibility results

Test target: Playwright Chromium, Linux, ordinary browser contexts, no native IWA features enabled. The following are exercised behaviors, not general claims about all IWAs.

| --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [ChromeOS IWA Kitchen Sink](https://github.com/chromeos/iwa-sink/releases/tag/v1.7.0), 1.7.0                                            | Upload the upstream signed bundle, launch `/`, create a TCP client using the actual app button, send a message from the client, and send a reply from the server. Assert the app received both payloads. Also import its public `update.json` through the URL form, resolve the release asset, and launch it. |
| [IWA Bundling Example](https://github.com/michaelwasserman/iwa-bundling-example/tree/ef59ada5649cef9f669d1d9a3fb53f5a5b5bca58), 1.0.0   | Upload, verify, launch, and check the visible app heading.                                                                                                                                                                                                                                                    |

## Synthetic package and integration tests

The Kitchen Sink regression tests also click **Capture the screens** and play the resulting video using Chromium's test display source; click **Go unframed** and check its inline CSS and a live media-query listener after granting window management; run the color/text controls on a Scramjet-proxied publisher fixture; and complete the OAuth form, callback, and token exchange against a test issuer. Windowing Example opens its own popup document, uses its opener-side handle, and observes closure. In a separate live check, MDN's DOM examples rendered in Kitchen Sink's controlled frame, while Google's `SAMEORIGIN` response produced the external-site link.

- Verify signatures using current and historical reference signers with **both Ed25519 and P-256**. Reject payload corruption, identity substitution, missing start paths, downgrades, and version conflicts. Reload the library from disk.
- Resolve root-relative assets, nested ES modules, dynamic browser fetches, and binary byte ranges. Run a module worker, then install the **app's own** root-scoped service worker and fetch a response generated by it.
- Load the standalone SDK without using the sample UI for launch; follow a manifest protocol handler, preserve site storage across navigation, and deliver a second in-tab launch event.
- Virtual IPv6 TCP listen/connect/accept/BYOB/EOF; virtual connected and bound UDP and multicast; dedicated worker → window TCP. Wisp round trips against real TCP and UDP echo fixtures. With explicit listener grants, independent OS clients connect to a browser-app TCP listener and receive a reply from its bound IPv6 UDP socket.
- Real Scramjet-rewritten managed HTML, script and JSON fetch. Execute script, insert visible CSS, clear storage, change zoom, click a custom guest context-menu item, and deliver its ID to the app. Navigate to a separate publisher-opted-in origin, observe separate storage, modify an HTTP request header and read it back at the server, block another request, then go back to the original partition.

## Where behavior differs from ChromeOS

| Area               | Boundary                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Origin             | Native `location`, `URL.origin`, user permissions and credentials belong to the real localhost app origin. Same-ID literal `isolated-app:` URLs in packaged text assets and same-ID string/URL fetch inputs are translated. Runtime launch events expose the virtual URL. This is not a system-wide implementation of the scheme.                                                                                                                                                                                                                                                                    |
| Package policies   | Script/style/network policy and the package CSP are applied together. A bundled `frame-ancestors 'self'` is mapped to include the launcher, and managed frames need local partition origins in `frame-src`. COEP uses `credentialless`. The compatibility environment does not provide native IWA security guarantees.                                                                                                                                                                                                                                                                               |
| Updates            | Explicit update checks and channel selection, with signing-ID continuity. No enterprise allowlist, automatic update scheduler, or external key-rotation authority. Legacy `1b` support covers the single-signature format generated by the historical Node signer.                                                                                                                                                                                                                                                                                                                                   |
| Network            | Wisp has no remote TCP handshake acknowledgment or local endpoint report: `opened` means the relay stream was created; a subsequent error can still close it. OS-level tuning such as keepalive/buffer sizes is not fully mapped. Virtual TCP closes both ends; it is not a complete TCP stack. Real listeners are loopback only. Multicast is virtual, not physical LAN broadcast/discovery.                                                                                                                                                                                                        |
| Workers            | Window and app-created dedicated worker networking are tested. Service workers can serve app content natively; the in-page virtual network is not available to an independently started service worker. Blob workers and module dependencies executing before their entry module may lack the bootstrap.                                                                                                                                                                                                                                                                                             |
| Frames             | Controlled-frame navigations use Scramjet. Public source requests are anonymous, read-only and scoped to a partition origin. Responses with restrictive framing headers or a CSP the runtime cannot preserve are declined. Top-level HTTP redirects get their own origin partition when needed. Managed `executeScript` runs in the guest realm, not a Chrome isolated world. Cross-origin subresources, managed WebSockets and browser sign-in cookies are not supported.                                                                                                                           |
| Frame management   | Managed lifecycle notifications, programmatic history, and guest context menus are emulated. Request interception is not Chromium's complete `webRequest` API; parser preloads, all redirects, header phases, and subframe-initiated navigation are not all observable. `clearData` supports whole selected stores, not arbitrary timestamp ranges. Modal dialogs and browser permission prompts cannot be synchronously mediated like native controlled frames. Nonpersistent partitions get new origins on relaunch; browser data from an abandoned origin is subject to browser storage eviction. |
| System integration | Browser fullscreen, screen/window management, hardware access, downloads and capture remain subject to browser support, user activation and permission. `getAllScreensMedia` returns one user-selected stream. Unframed mode updates inline/linked stylesheets and JS queries on permission changes. App-owned popup bounds are constrained to the app viewport; they are not OS windows on a second monitor. There is no enterprise auto-grant, extension IPC, or system protocol registration.                                                                                                     |
