# Compatibility

Test target: Playwright's Chromium on Linux, in ordinary browser contexts with no native IWA features. Everything listed under **Tested** is checked by an automated test. Everything else is a stated boundary, not a guess.

## Tested with signed fixtures (`pnpm test`)

- **Bundles:** Ed25519 and P-256, current and legacy `1b` integrity blocks, tamper and identity-forgery rejection, downgrade and conflict refusal, update-channel selection, icon choice, and a library plus permissions that survive restarts.
- **App documents:** ES modules, module workers, byte ranges, and the app's **own service worker**. Protocol handlers, `launchQueue`, and storage persistence work across navigations.
- **Sockets:** in-app TCP listen, accept, BYOB, and EOF; UDP and multicast; dedicated worker to window. With access allowed, Wisp reaches real TCP and UDP services, `opened` rejects for refused ports, and OS clients connect to app listeners. Undeclared capabilities throw `NotAllowedError`.
- **Controlled frames:** bundled pages and a site that sends `X-Frame-Options: DENY` with `frame-ancestors 'none'`. Tests cover CSS and script injection, `clearData`, zoom, in-page link navigation with `back()` and `canGoBack()`, interceptors that block a request and rewrite a header read by the server, cookies from `Set-Cookie`, WebSockets from the page, `window.open` → `newwindow`, custom context menus, and a refused LAN page when access is blocked.
- **Launcher:** install an example, answer and remember the prompt, inspect sockets, console, and permissions, restore the open app after reload, and remove it. A bad bundle shows an error, and a chosen file installs and opens.

## Where behavior differs from ChromeOS

| Area               | Boundary                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Origin             | Apps really run at `http://<id>.localhost:<port>`. `isolated-app://<id>/` URLs in HTML, scripts and `fetch()` are translated, and launch events and the toolbar show the virtual URL, but `location.origin` is the real one. Browser permission prompts name `<id>.localhost`.                                                                                                                                                                        |
| Security           | The IWA CSP baseline, COOP, COEP (`credentialless`), and the manifest's Permissions Policy are applied by headers. This is a compatibility environment, not Chrome's IWA isolation guarantee: anything else running on your machine can reach `localhost`.                                                                                                                                                                                            |
| Updates            | Explicit checks with signing-key continuity. No background updater, enterprise allowlist, or key rotation.                                                                                                                                                                                                                                                                                                                                            |
| Sockets            | TCP keepalive, buffer sizes, and `dnsQueryType` are accepted but not all mapped to the OS. The in-app network is not a full TCP stack. Multicast is in-app, or uses a real bound socket's group membership when access is allowed. Dedicated workers see the permission state from when they started, because they can't prompt.                                                                                                                      |
| Frame proxy        | Scramjet only proxies `http(s)`. Bundled pages shown in a frame run under the stand-in origin `https://bundle.invalid`; the frame's `src` and events still report `isolated-app://`. Sites' own service workers don't run inside frames, because Scramjet removes `navigator.serviceWorker`. Browser sign-ins and cookies from your real profile aren't shared.                                                                                       |
| Bot checks         | Some sites challenge proxied traffic. In headless tests, a Google search submitted from the frame hit Google's "unusual traffic" page, whose challenge script fails under the proxy (`solveSimpleChallenge is not defined`). The Google home page and other sites work.                                                                                                                                                                               |
| Frame API edges    | `executeScript` runs in the page's main world, not an isolated world. Interceptors see requests that pass through the partition service worker, which excludes parser preloads and requests the browser makes without it. `clearData` clears whole stores, not time ranges. `find` reports at most one match. `captureVisibleRegion` throws `NotSupportedError`. `dialog` and `permissionrequest` events aren't raised: page dialogs appear natively. |
| System integration | Fullscreen, window management, capture, and hardware APIs still go through Chromium's own prompts and user-activation rules. `getAllScreensMedia` returns the one surface you pick. App popups are in-tab windows, not OS windows. There's no OS protocol registration or file handling.                                                                                                                                                              |
